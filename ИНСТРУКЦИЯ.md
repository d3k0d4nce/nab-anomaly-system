# Инструкция по локальному запуску NAB Anomaly System

Проект можно запустить двумя способами:

1. **Docker Compose** — рекомендуется. Нужен только Docker, Python и PostgreSQL
   устанавливать не нужно.
2. **Локально через Python** — нужны Python 3.9+ и PostgreSQL 16.

В репозитории **нет** виртуального окружения, скачанного датасета NAB (~350 МБ)
и сгенерированных отчётов/моделей. Всё это создаётся при первом запуске.
Нужен доступ в интернет: pipeline сам клонирует NAB с GitHub.

---

## Вариант 1. Docker Compose (рекомендуется)

### Что установить

- Docker Desktop (macOS/Windows) или Docker Engine + Compose plugin (Linux).
- Git — чтобы клонировать репозиторий.

Проверить:

```bash
docker --version
docker compose version
```

### Запуск

```bash
git clone <ссылка-на-репозиторий> nab-anomaly-system
cd nab-anomaly-system

cp .env.example .env
```

Откройте `.env` и обязательно измените:

- `NAB_SECRET_KEY` — случайная строка. Сгенерировать:
  ```bash
  python3 -c "import secrets; print(secrets.token_hex(32))"
  ```
  (или `openssl rand -hex 32`);
- `NAB_OPERATOR_PASSWORD` и `NAB_ADMIN_PASSWORD` — пароли демо-аккаунтов.

Остальные значения можно оставить по умолчанию.

Запустить:

```bash
docker compose up --build -d
```

Первый запуск занимает несколько минут: контейнер скачивает NAB, выполняет
audit, обучает детекторы и заполняет PostgreSQL. Следить за прогрессом:

```bash
docker compose logs -f app
```

Когда сервис поднимется, открыть:

```text
http://127.0.0.1:8081
```

Проверка состояния:

```bash
curl http://127.0.0.1:8081/health
```

### Логины

| Роль | Логин | Пароль по умолчанию |
|---|---|---|
| Дежурный инженер | `operator` | `demo-operator` |
| Администратор | `admin` | `demo-admin` |

Пароли берутся из `.env` и перезаписываются при старте приложения.

### Остановка и очистка

```bash
docker compose down       # остановить, данные сохраняются
docker compose down -v    # остановить и удалить БД/данные/отчёты
```

Принудительно пересобрать данные и модели:

```bash
NAB_RUN_PIPELINE=1 docker compose up --build -d
```

Скопировать отчёт из контейнера:

```bash
docker compose cp app:/app/reports/final_report.md ./final_report.md
```

Если порт `8081` занят, поменяйте `NAB_HTTP_PORT` в `.env` и перезапустите
`docker compose up -d`.

## Вариант 2. Локально через Python

### 2.1. Требования

- Python 3.9+ (рекомендуется 3.11 или 3.12);
- PostgreSQL 16;
- Git (нужен для автоматической загрузки NAB);
- macOS, Linux или Windows.

### 2.2. Клонирование и виртуальное окружение

```bash
git clone <ссылка-на-репозиторий> nab-anomaly-system
cd nab-anomaly-system

python3 -m venv .venv
source .venv/bin/activate          # macOS/Linux
# .venv\Scripts\activate           # Windows (PowerShell/CMD)

pip install --upgrade pip
pip install -r requirements.txt
pip install -e .
```

### 2.3. PostgreSQL

Приложение само создаёт базу `nab_anomaly`, но роль PostgreSQL должна
существовать заранее. Выберите свой случай.

**macOS (Homebrew):**

```bash
brew install postgresql@16
brew services start postgresql@16
```

Пользователь по умолчанию — ваше имя пользователя macOS, пароль пустой.
Ничего дополнительно настраивать не нужно.

**Linux (Ubuntu/Debian):**

```bash
sudo apt update
sudo apt install -y postgresql postgresql-contrib
sudo systemctl start postgresql
sudo -u postgres psql -c "ALTER USER postgres PASSWORD 'postgres';"
```

**Windows:**

Установите PostgreSQL 16 с официального сайта. При установке задайте пароль
пользователя `postgres`.

**Проверка подключения:**

```bash
psql -d postgres -c "SELECT 1;"
```

### 2.4. Переменные окружения для базы

Если параметры по умолчанию не подходят, задайте их в shell **перед** запуском.

macOS/Homebrew (обычно не требуется):

```bash
export PGHOST=localhost
export PGPORT=5432
export PGDATABASE=nab_anomaly
# PGUSER/PGPASSWORD можно не задавать: возьмётся текущий пользователь ОС
```

Linux/Windows (пользователь `postgres`):

```bash
export PGHOST=localhost
export PGPORT=5432
export PGDATABASE=nab_anomaly
export PGUSER=postgres
export PGPASSWORD=postgres
```

PowerShell:

```powershell
$env:PGHOST="localhost"
$env:PGPORT="5432"
$env:PGDATABASE="nab_anomaly"
$env:PGUSER="postgres"
$env:PGPASSWORD="<пароль>"
```

Важно: локальный запуск **не читает `.env`** — это делает только Docker
Compose. Для локального запуска нужны настоящие переменные окружения.

### 2.5. Первый запуск pipeline

```bash
# audit + скачивание NAB + обучение + оценка + запись в PostgreSQL
python -m nab_system.cli pipeline
```

При первом запуске команда клонирует NAB в `data/raw/NAB`. Это долго:
несколько минут и ~350 МБ. Нужны `git` и интернет.

Полезные варианты:

```bash
python -m nab_system.cli pipeline --no-reset   # не удалять текущие данные
python -m nab_system.cli pipeline --no-stress  # без stress-серий (быстрее)
python -m nab_system.cli init-db --reset       # только пересоздать таблицы
python -m nab_system.cli demo                  # replay normal -> failure -> recovery
python -m nab_system.cli report                # фигуры и final_report.md
```

### 2.6. Запуск сервиса

```bash
python -m nab_system.cli serve --host 127.0.0.1 --port 8000
```

Открыть:

```text
http://127.0.0.1:8000
```

Проверка:

```bash
curl http://127.0.0.1:8000/health
```

Пароли по умолчанию те же: `operator / demo-operator`, `admin / demo-admin`.
Их можно переопределить переменными окружения:

```bash
export NAB_SECRET_KEY="$(python3 -c 'import secrets; print(secrets.token_hex(32))')"
export NAB_OPERATOR_LOGIN=operator
export NAB_OPERATOR_PASSWORD=my-operator-password
export NAB_ADMIN_LOGIN=admin
export NAB_ADMIN_PASSWORD=my-admin-password
python -m nab_system.cli serve --port 8000
```

### 2.7. Запуск в фоне (macOS/Linux)

```bash
nohup .venv/bin/python -m nab_system.cli serve --port 8000 \
  >/tmp/nab_serve.log 2>&1 </dev/null &
echo $! >/tmp/nab_serve.pid
```

Остановить:

```bash
kill "$(cat /tmp/nab_serve.pid)"
```

Лог:

```bash
tail -f /tmp/nab_serve.log
```

## Демо для показа

### Дежурный инженер

1. Войти как `operator` (пароль из `.env` или `demo-operator`).
2. Показать фильтры алертов: статус, тип, ряд.
3. Показать пагинацию алертов и таблицы качества детекции.
4. Взять алерт в работу, подтвердить реальный сбой или отметить ложную тревогу.
5. Закрыть подтверждённый алерт.

### Администратор

1. Войти как `admin`.
2. Открыть dashboard.
3. Показать блок «Ручная точка».
4. Выбрать ряд, ввести новый timestamp и значение.
5. Нажать «Отправить».

Пример ручной точки:

```text
Ряд: ec2_request_latency_system_failure
Время: 2014-03-19 04:30:00
Значение: 70.0
```

Timestamp должен отсутствовать в базе, иначе вернётся `409`. Ответ `SKIP` с
причиной «внутри активного эпизода» — нормальное поведение: система не создаёт
дубликаты алертов внутри одного сбоя.

- `/` — dashboard
- `/login`, `/logout` — вход и выход
- `/health` — состояние сервиса
- `/me` — текущий пользователь
- `/series` — список рядов

## Частые проблемы

### Порт занят

```bash
lsof -nP -iTCP:8000 -sTCP:LISTEN     # macOS/Linux
kill <PID>
```

Или запустить на другом порту: `--port 8001` (локально) либо изменить
`NAB_HTTP_PORT` (Docker).

### Нет подключения к PostgreSQL

```bash
# macOS
brew services list
psql -d postgres -c "SELECT 1;"

# Linux
sudo systemctl status postgresql
```

Проверьте `PGHOST`, `PGPORT`, `PGUSER`, `PGPASSWORD`. Частая причина —
роль `PGUSER` не существует или неверный пароль.

### Ошибка `FATAL: role "..." does not exist`

Укажите существующую роль:

```bash
export PGUSER=postgres
export PGPASSWORD=<пароль>
```

Либо создайте роль (Linux/macOS):

```bash
sudo -u postgres createuser -s "$USER"
```

### Не скачивается NAB

Нужен установленный `git` и доступ в интернет. Проверить вручную:

```bash
git clone --depth 1 https://github.com/numenta/NAB.git data/raw/NAB
```

Затем повторить `python -m nab_system.cli pipeline`.

### Не найден детектор

Выполните pipeline — он создаёт модели в `artifacts/detectors`:

```bash
python -m nab_system.cli pipeline
```

### Ошибка установки `psycopg2-binary`

Обычно помогает Python 3.11/3.12 и свежий pip:

```bash
pip install --upgrade pip
pip install -r requirements.txt
```

### После изменения кода не видно изменений

Перезапустите сервис и обновите страницу с очисткой кэша
(`Cmd + Shift + R` / `Ctrl + F5`).

### Долгий первый запуск Docker

Это нормально: скачивается NAB, обучаются детекторы, заполняется БД.
Смотрите прогресс в `docker compose logs -f app`.
